# Alpha Dental — iOS app

The website (https://alphadental.app) inside a native iOS shell, built with
[Capacitor](https://capacitorjs.com). Not a rewrite: the app opens the live site in a
WKWebView, so every deploy to Vercel reaches every iPhone the moment it goes live
and there is no second copy of the screens to keep in step.

This is the deliberate first step for iOS — a store listing, push notifications and
a home-screen icon in weeks. The native Android app (`../android`) explains why it
went further; the same can be done here later without throwing this away.

What it gives you over Safari's "Add to Home Screen":

- **Push notifications** through APNs, registered with the same server route a
  browser uses, so every alert in the notification catalogue reaches the phone.
- An **App Store / TestFlight** listing staff can install from.
- A proper icon, splash screen and keyboard handling.

What it does **not** do, by design:

- Nothing works offline except a "could not reach the system" page (`../ios-web`).
- **Google sign-in is hidden** inside the app, as it is in the Android app: a
  WKWebView cannot open Firebase's sign-in popup. Staff sign in with email and
  password; anyone who only ever used Google sets a password with
  **Forgot Password?** in a normal browser first.
- No SMS from the phone's SIM — iOS forbids it. Reminders keep going through the
  server-side channels.

## Files

| Path | What |
|---|---|
| `../capacitor.config.ts` | App id, name, the site URL the shell loads, plugin settings |
| `../ios-web/index.html` | The only page bundled: shown when the site cannot be reached |
| `App/App/AppDelegate.swift` | Hands the APNs device token to the Firebase Messaging plugin |
| `App/App/App.entitlements` | `aps-environment` — push capability |
| `App/App/Info.plist` | Display name, `remote-notification` background mode |
| `App/CapApp-SPM/` | Swift Package Manager manifest generated by `npm run ios:sync` |
| `App/App/GoogleService-Info.plist` | **Not in git.** Downloaded per project, see below |

The web side knows it is inside the shell through `src/lib/native.ts`; the only
places that ask are `src/lib/fcmClient.ts` (push), `src/components/NotificationBell.tsx`
(the enable-notifications button) and `src/app/login/page.tsx` (hides Google).

## Building — needs a Mac

1. **Tools**: Xcode 16 or newer from the App Store, Node 20+, and an
   [Apple Developer account](https://developer.apple.com/programs/) (99 USD/year).
   CocoaPods is not needed; the project uses Swift Package Manager.
2. In the repository root: `npm install` then `npm run ios:sync`.
3. **Firebase**: in the Firebase console for project `alpha-v2-ffc98`, add an iOS app
   with bundle id `com.alphadental.clinic`, download `GoogleService-Info.plist`, and
   drag it into Xcode under `App/App` (tick "Copy items if needed" and the App target).
   It is git-ignored on purpose, like `android/firebase.properties`.
4. **Push**: in the Apple developer portal create an **APNs Auth Key** (Keys → +,
   tick Apple Push Notifications service). Upload the `.p8`, its Key ID and the
   Team ID under Firebase → Project settings → Cloud Messaging → Apple app
   configuration. Without this step the app installs and runs but
   "Enable notifications" fails quietly.
5. `npm run ios:open`, pick your team under **Signing & Capabilities**, and confirm
   the **Push Notifications** and **Background Modes → Remote notifications**
   capabilities are listed (the entitlements file already declares them).
6. Run on a real iPhone first. The simulator cannot receive push.

For TestFlight and the store: Product → Archive, then Distribute. Change
`App.entitlements` `aps-environment` to `production` for store builds — Xcode does
this automatically when archiving with automatic signing.

## What to check after installing

| # | Do this | What should happen |
|---|---|---|
| 1 | Open the app | Splash, then the login page with **no** Google button |
| 2 | Sign in with email and password | The dashboard, exactly as in Safari |
| 3 | Open the bell, tap enable notifications | iOS asks for permission; the button disappears |
| 4 | Have reception raise any alert | A banner arrives on the lock screen |
| 5 | Tap a WhatsApp link on a patient | Leaves the app and opens WhatsApp |
| 6 | Turn on aeroplane mode, kill and reopen the app | The "could not reach the system" page with a retry button |
| 7 | Rotate the phone | The layout follows; nothing is cut off by the notch |

## Updating

- A change to the **website** needs nothing here. Ship it to Vercel as usual.
- A change to `capacitor.config.ts` or a new Capacitor plugin: `npm run ios:sync`,
  then rebuild in Xcode.
- A new Capacitor major: `npm install @capacitor/core@latest @capacitor/cli@latest
  @capacitor/ios@latest` plus the plugins, then `npx cap migrate`.

## Why these choices

- **`server.url` rather than a static export.** The site is a Next.js app with server
  routes and server-rendered pages; it cannot be exported to static files, so the
  shell loads it over the network like any browser.
- **The Firebase plugin rather than `@capacitor/push-notifications`.** The latter
  gives an APNs token, which none of the server's senders understand. The Firebase
  plugin exchanges it for an FCM token on the phone, so `/api/push/register-token`
  and everything behind it stay untouched.
- **Same bundle id as Android.** One app in Firebase, in the push catalogue and in
  support conversations.
