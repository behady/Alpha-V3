# Excel backup for clinic owners — design

**Date:** 2026-09-30
**Status:** agreed in chat (delivery, sheets, ledger view, header language); awaiting review of this write-up.

## What this is

A clinic Owner or Admin opens **Settings → System → Backup**, presses one button, and the browser downloads
one `.xlsx` workbook holding the clinic's records in a form a person can read in Excel without knowing the
system: one sheet per kind of record, bilingual headers, real numbers in money columns, per-patient balances.

It is a *human-readable export*, not a restore file. Nothing imports it back. The existing migration importer
(`tests/backupImport.test.mts`) is a different thing and is untouched.

## Decisions taken with the owner (2026-09-30)

| Question | Answer |
| --- | --- |
| Delivery | Download button only. No schedule, no email, no Android screen. |
| Sheets beyond patients/appointments/ledger | Lab orders + lab payments; staff, price lists, expenses; attendance/payroll. **Not** clinical notes or treatment plans, **not** leads/chats. |
| Ledger view | Both: a full row-per-transaction Ledger sheet, and charged/paid/owed columns on the Patients sheet. |
| Header language | Bilingual, every header `English - العربية`. |

## Assumptions (not asked; change here if wrong)

- Not behind an add-on. A clinic's own data is always downloadable by its Admin/Owner.
- Whole history, no date filter. The workbook is the backup; filtering is what Reports are for.
- Salaries appear on the Staff and Payroll sheets. The route is Admin/Owner-only, which is who sees them today.
- Recently-deleted (bin) records are not included. They are not the clinic's live data.
- Superadmin can pull any clinic's file (it passes `requireAdminUser`); nothing extra is built for that.

## Architecture

Three units, one direction of dependency:

```
BackupSettings.tsx  ──fetch──▶  /api/records/backup  ──▶ loadClinicBackupData(clinicId)   [firebase-admin reads]
   (panel + button)               (auth, headers)          │
                                                           ▼
                                                    buildClinicWorkbook(data)   [pure; xlsx only; tested]
```

- **`src/lib/backup/types.ts`** — `ClinicBackupData`: plain arrays, no Firestore types, so the builder is
  testable with fixtures exactly like `ledgerWrite.ts` and the briefing sections.
- **`src/lib/backup/loadClinicBackupData.ts`** — reads every collection with `adminClinicCollection`, paged
  by document id (`orderBy(FieldPath.documentId()).startAfter(last).limit(1000)`), no hard cap. Reuses the
  normalisers already in `src/lib/automation/briefing/data.ts` where they exist (staff, punches) by
  extracting them into exported functions; does not duplicate them.
- **`src/lib/backup/buildClinicWorkbook.ts`** — `ClinicBackupData → XLSX.WorkBook`. Firebase-free. All
  labels come from one `BACKUP_TEXT` table in `src/lib/backup/backupText.ts` so the Arabic is readable in one
  file (same reasoning as `settingsText.ts`).
- **`src/app/api/records/backup/route.ts`** — `GET ?clinicId=`; `requireAdminUser`; `resolveUserClinicId`;
  streams the buffer with `Content-Disposition: attachment`. `runtime = "nodejs"`, `maxDuration = 300`.
- **Settings**: registry section `backup` (group `system`, view+edit ADMIN, one `readOnly` target naming
  the route), `SETTINGS_TEXT.backup`, panel `src/components/settings/BackupSettings.tsx`, client call
  `src/lib/backupApi.ts` (same bearer-token pattern as `recycleBinApi.ts`).

## The workbook

Sheet names cannot contain `/`, so they use ` - `. Order as listed. Every sheet: header row bold, frozen,
column widths set, `rightToLeft` view when the requesting user's app language is Arabic. Text cells are text
(dates stay `yyyy-mm-dd` strings as stored; no timezone conversion); money and counts are numbers. A field
that is missing writes an empty cell, never the string `undefined`, `null` or `NaN`.

Enum values (status, ledger type, payment method, lab status, work type) are written bilingual too, e.g.
`Completed - مكتمل`, using the app's own label functions (`getAppointmentStageLabel`, `statusLabel`,
`workTypeLabel`, `LAB_PAYMENT_METHODS`).

1. **About - نبذة** — clinic name, generated at (clinic timezone), generated by (name), then one row per
   sheet with its row count, then the three money definitions in both languages: *Cash* is what
   `ledgerCashValue` returns; *Charged* is the price of procedure rows; *Balance owed* = charged − paid,
   negative means the patient has credit. Also: "Expenses appear both on the Ledger sheet and on their own sheet."
2. **Patients - المرضى** — File no. (`fileId`, e.g. PT-42), Name, Phone, Gender, Date of birth, Address,
   Branch, Source (`source`, else `referral`), Medical history, Allergies, Status, Registered on, First visit,
   Last visit, Visits, Total charged, Total paid, Balance owed, Patient ID. The last six come from
   `rollupPatients(procedures, payments, patientsById)` in `src/lib/reportPatients.ts`, fed only ledger rows
   whose `status` is not `deleted`/`cancelled` (the Reports Center's filter), so the file agrees with the
   Reports Center. A patient with no ledger rows still appears, with zeros and blank dates. Sorted by name.
3. **Appointments - المواعيد** — Date, Time, Patient, Phone, Dentist, Treatment, Status, Duration (min),
   Branch, Room, Source, Cost, Notes, Patient ID, Appointment ID. Sorted by date then time, oldest first.
4. **Ledger - السجل المالي** — Date, Type, Patient, Dentist, Treatment / description, Category,
   Payment method, Listed amount, Discount, Cash in, Cash out, Lab fee, Dentist commission, Clinic profit,
   Payer, Status, Patient ID, Row ID. *Cash in* = `ledgerCashValue(row)` for every type except `expense`;
   *Cash out* = `ledgerCashValue(row)` for `expense`; the other of the two is blank. Every row is written,
   including `deleted`/`cancelled` ones (that is what Status is for; a backup omits nothing). Type is
   bilingual from a new four-entry map (procedure/payment/income/expense) in `backupText.ts`; an unknown
   type is written as-is. Sorted by date, oldest first.
5. **Expenses - المصروفات** — Date, Description, Category, Payment method, Amount, Notes, Row ID. The
   `type === "expense"` rows of the ledger; Amount = `ledgerCashValue(row)`.
6. **Lab orders - طلبات المعمل** — Code, Sent, Due, Received, Fitted, Patient, Dentist, Lab, Work type,
   Teeth, Units, Body shade, Material, Agreed price, Status, Remake of, Remake reason, Fault, Order ID.
   Teeth joined with `, `. From `lab_cases`.
7. **Lab payments - مدفوعات المعامل** — Date, Lab, Amount, Method, Reference, Note, Payment ID. From
   `lab_payments`.
8. **Labs - المعامل** — Lab, Cases delivered, Owed for delivered, Still at lab, Paid, Balance, Remakes at
   lab cost. One row per lab from `labAccounts(labs, cases, payments)` (`src/lib/labAccounts.ts`); labs
   come from `settings/labs` via `parseDentalLabs`.
9. **Staff - الفريق** — Name, Role, Job title, Email, Phone, Active, Base salary, Commission %, Overtime
   multiplier, Working days (e.g. `Sun 10:00-18:00; Mon 10:00-18:00`), Staff ID.
10. **Prices - الأسعار** — Service, Category, Pricing mode, Needs lab, Estimated lab fee, Base price, then
    **one column per price list** (header = list name, Arabic name if set) holding `service.prices[list.id]`
    or blank. Lists from `settings/price_lists` via `parsePriceLists`; inactive lists still get a column
    (suffix ` (inactive)`), because old rows were priced from them.
11. **Attendance - الحضور** — Date, Staff, Check in, Check out, Hours, Status, Overtime status,
    Punch ID. Punches only (`userId` non-empty), times as `HH:mm` in the clinic timezone. Sorted by date.
12. **Payroll - الرواتب** — Month, Staff, Role, Scheduled days, Days worked, Hours worked, Late days,
    Absent days, Overtime approved (h), Overtime pending (h), Estimated pay. One row per staff per calendar
    month that has at least one punch, computed by `buildHrSection` (`src/lib/automation/briefing/hr.ts`)
    with `startDate`/`monthStart` = first of that month and `endDate` = last day of that month (or today for
    the current month). Same arithmetic as the Attendance screen and `/api/payroll`; no new formula.

## Access and safety

- Route: `requireAdminUser(request, clinicId, { allowInactive: true })` — Owner or Admin of *that* clinic,
  or superadmin. Everyone else gets the 403 the helper already produces. `allowInactive` is deliberate: a
  clinic whose subscription lapsed must still be able to take its own data out. `tests/permissions.test.mts`
  pins the list of routes exempt from the expiry gate; this route is added there with that reason.
  `resolveUserClinicId` picks the clinic, never the query string alone.
- Every successful download is written to the clinic's activity log through `logActivityServer`
  (`src/lib/server/systemLog.ts`), so an owner can see who took a copy and when.
- Settings section `view` and `edit` are both `{ kind: "admin" }`, so the sidebar hides it from staff and
  typing the URL shows the standard "locked" panel.
- Response headers: `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`,
  `Content-Disposition: attachment; filename="alpha-backup-<YYYY-MM-DD>.xlsx"` (ASCII only; the clinic name
  is inside the file), `Cache-Control: no-store`.
- Failure: `reportServerError("[Backup] failed", e)` and `{ ok:false, error }` with 500. The panel shows the
  server's message in a toast. No partial file is ever sent.
- No rate limit. Admin-only and one click; add one later only if it is abused.

## Client behaviour

Panel text (EN/AR in `SETTINGS_TEXT.backup`): title, one-paragraph explanation, a bullet list naming the
twelve sheets, a note that it is not a restore file, and the button **Download Excel backup / تنزيل نسخة
Excel**. While building: button disabled with a spinner and "Preparing your file — a large clinic can take a
minute". On success: toast "Backup downloaded". On error: toast with the server message. `downloadClinicBackup`
fetches with the bearer token, reads the blob, and triggers a download through a temporary anchor (the
hidden-iframe trick is not used; see the print bug on mobile).

## Testing

- `tests/clinicBackup.test.mts` (npm script `test:excel-backup`, tsx, no emulator): fixtures → workbook →
  `XLSX.utils.sheet_to_json` → asserts. Covers: sheet names and order; a bilingual header; balance math
  agreeing with `rollupPatients`; the placeholder-zero payment counts as cash (the `??` trap); an expense
  lands in Cash out and on the Expenses sheet and never in a patient balance; a patient with no rows appears;
  an unknown appointment status is written as-is, not dropped; a missing field is an empty cell; Arabic text
  round-trips; RTL view flag follows language; a price list column per list including an inactive one;
  payroll months are split correctly and match `buildHrSection`.
- `npm run test:settings` must still pass (registry hygiene) and `npm run test:permissions`.
- Manual: download from the demo clinic and from the owner's real clinic; open in Excel and LibreOffice; check
  Arabic renders and the About counts equal the sheet row counts.

## Out of scope (deliberately)

Scheduled/emailed backups; Android; clinical notes, treatment plans, x-ray reports, leads, chats; a restore
path; per-branch or date-range filtering; a help-center article and Sara tour step (add after it ships).
